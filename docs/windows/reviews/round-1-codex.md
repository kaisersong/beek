# Codex 独立对抗评审 — Round 1

- 被评版本：v1。
- SHA-256：`4d22415b8955bb0897b95f99bd994ba3cf25ff10760beb150b62df12ad242a4d`。
- Verdict：REVISE。
- 本意见在阅读 xiaok/Kimi 的实质评审结果前形成；未实施 Windows 代码。

## CODEX-R1-01 — Major：翻译取消仅在 UI 层定义，网络工作和队列无资源上限

§4–5 规定取词消息有界，但 §1、§10 仅要求旧翻译响应不能复活弹窗。现有 `src/translate.rs` 使用阻塞请求，关闭窗口不会自然结束后台请求；用户连续点击不同选区可堆积网络线程和流式消息。16K 选区上限也不约束模型输出。

最小修正：定义模型请求并发上限、待执行最新请求数量、输出字节/字符上限、SSE 单帧上限、总超时、取消语义和 chunk 背压。沿用 blocking 时明确逻辑取消不释放真实工作槽，禁止无限 spawn。

关闭标准：持续开关弹窗、慢响应和恶意长流场景下，线程数和队列深度可证明有界，取消结果不显示，不产生 UI 卡顿。

## CODEX-R1-02 — Major：重启与单实例交接缺少协议

§8 仅写“显式拉起 current_exe 并完成交接”。若先拉起再释放 mutex，新进程可能按普通第二实例路径立即退出；若先释放且启动失败，BeeK 则完全退出。

最小修正：定义重启专用参数和父进程标识、启动/就绪握手、等待旧实例退出与锁获取、启动失败保留旧实例，以及超时反馈。身份需包含进程创建时间/真实进程句柄，避免 PID 复用。

关闭标准：重启成功、子进程无法启动、父进程不退出、普通重复启动四种场景均有明确结果，没有两个主实例或无反馈退出。

## CODEX-R1-03 — Major：剪贴板更新不能被可靠归属给当前前台应用

§6.1 的“仅接受当前外部交互源”缺乏来源证明。复制后切换应用、后台密码管理器更新、远程同步/历史恢复均可使剪贴板文本与前台源不一致。当前 source token 定义不可表达“来源未知”。

最小修正：区分 UIA 选区来源和剪贴板来源，未知来源不伪造 HWND 绑定；定义可信关联条件与失败关闭规则。用户主动“读取剪贴板”可作为独立一次性动作，但在预览和点击前不请求模型。

关闭标准：后台写入、切换应用、未知 owner、自身复制、密码管理器场景没有错误来源归属和自动网络请求；开关关闭时仍有明确可操作的降级说明。

## CODEX-R1-04 — Major：公开支持清单存在可被降级冲淡的验收空间

§1 要求浏览器等 L1 自动划词，但 §10 允许按实测填写 L1/L2。若所有软件都被标 L2，G5 仍可能被宣称通过，实际失去产品核心目标。

最小修正：固定最小 L1 集合（Windows 11 记事本、Edge 普通网页、Chrome 普通网页）及具体必测场景。Word/VS Code/Terminal/PDF 可以按实测标级，但不可把 L1 硬门槛降为复制降级后仍通过。

关闭标准：最低集合任何 L1 失败均阻止 G5；浏览器受限页面和扫描 PDF 另列排除，不能混用以制造成功率。

## CODEX-R1-05 — Minor：安装器选择留白，AI 任务尚不能直接执行

§9.1 留到 G0 后选 installer，但 G5 缺少选择标准、负责点和失败回退。建议预选一个工具（例如固定版 Inno Setup，经过官方文档及许可确认）并列需要验证的用户级安装、静默参数、升级进程处理和退出码；失败需修订方案而非现场加入第二套框架。

关闭标准：任务输入中有唯一选型和可检验的安装/升级/卸载协议；具体固定版本允许在 G0 环境清单中记录。

## CODEX-R1-06 — Major：同一 HWND 内切页和选区失效不足以由前台 token 发现

§5.1 只明确了切换应用、开始新选区、打开设置或锁屏使 generation 失效。同一浏览器窗口换标签、同一编辑器换文档，甚至普通输入取消原选区都可能保持 HWND/PID 不变。点击旧小蜜蜂会翻译与当前文档不符的缓存文本。

最小修正：定义同一源内缓存失效事件、selection identity 和短 TTL；点击时重新验证 UIA 选区身份和文本是否一致，验证失败不发送请求。显式剪贴板预览为单独确认过的文本快照，不按 UIA 路径强行复查。

关闭标准：同 HWND 切标签/切文档/取消选区、后台文档更新和迟到 UIA 事件不能让旧小蜜蜂触发错误请求。

## 赞同的主要设计

保留 GPUI 先证伪、UIA helper 进程隔离、首版关闭自动复制、手动签名安装、分平台依赖、保留 macOS 旧资产名和三方同 SHA 签核的方向合理。设计门禁可尚未运行，但不能在记录中变成已通过运行测试。
