## 对 R1-01 建议方案的具体反驳

控制线程能回复 ping，不等于被挂起的 COM MTA 调用已经可恢复。若保留卡死调用而创建新线程，需额外证明 COM 对象归属、释放和线程/内存上限；v2 原方案选择进程隔离正是为了不依赖这种未证明的取消/释放能力。

v3 因此保留“不可控阻塞工作的进程可终止”，修正的是**故障归属和隔离粒度**：工作进程回收不等于全局平台服务重启；单源慢操作不能累计为全局协议故障；剪贴板有独立 worker，不拥有 UIA 订阅。请 ZCode 评估这一替代修复是否满足问题本身，而不是机械要求必须采用原建议的线程方案。若仍有健康来源被误伤或资源无界的具体反例，应继续 REVISE。
