## 主动检查的反例与界限

1. 两个进程都在终止且尚未退出时，健康来源不得突破两个进程上限；方案给出300ms Busy及反馈，不承诺任何恶劣provider条件下都成功。真正支持应用的p95、成功率和超时率仍须G2/G5实测，Busy不能隐去。
2. 单一来源订阅回调崩溃不是无来源故障，不能逃过退避；相反，尚未绑定来源的启动失败走基础设施暂停，不能无限创建。成功查询清零连续故障是明确选择，不影响滚动创建速率上限。
3. 剪贴板等待超时后reader稍晚退出不会重新弹出旧内容；仅显式动作可以新建请求。新复制替换pending后仍以新请求的入队时间计，不延长原请求。
4. 来源切换与同HWND文档切换有generation/epoch、TTL和点击前复核；剪贴板快照另行确认；未恢复对未知源自动请求模型的路径。
5. 翻译真实槽与逻辑取消、凭据跨存储提交、重启父子握手、独立G0 probe/IME、固定L1集合、双平台发布资产及首版手动签名安装均保留先前修复。
6. 用户选择的Codex + ZCode两方阵容已写入§12；没有把缺席方失败改成通过。签核材料只证明设计，未来Windows门禁仍未运行。
